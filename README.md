# Weighbridge 120T — Web + Windows

نظام إدارة وقراءة أوزان ميزان البسكول بإصدارين يشتركان في نفس واجهة التشغيل ومنطق تسجيل الوزن:

1. **Web Edition:** يعمل من المتصفح، ويمكن نشره على GitHub Pages.
2. **Windows Edition:** تطبيق سطح مكتب مستقل يعمل محليًا دون إنترنت بعد تثبيته.

## نسخة الويب

- افتح الموقع المنشور أو افتح `index.html` من خلال خادم ملفات محلي.
- إدخال الوزن يدويًا عند الحاجة من 0 إلى 500,000 كجم.
- دورة وزن أول وثانٍ وحساب صافي الحمولة.
- سجل تذاكر وتقارير وطباعة وتصدير CSV / Excel.
- حفظ محلي داخل المتصفح.
- Web Serial متاح في المتصفحات الداعمة وعبر سياق آمن.

## نسخة Windows — Offline

تطبيق Electron مع SQLite ومحركات اتصال محلية:

- لا يحتاج اتصال إنترنت عند التشغيل.
- قاعدة البيانات تحفظ في مجلد بيانات المستخدم الخاص بالتطبيق، داخل ملف `weighbridge.sqlite`.
- حفظ سجلات الوزن والإعدادات محليًا، وتظل البيانات بعد إغلاق التطبيق وإعادة تشغيل الكمبيوتر.
- اكتشاف تلقائي لمنافذ COM/USB-to-Serial عند توصيل الكابل، مع إعادة مراقبة المنافذ كل ثانيتين وإعادة المحاولة عند فصل الكابل أو توصيله.
- ترتيب منافذ USB-to-Serial المعروفة أولًا، وتجربة سرعات الاتصال الشائعة وصيغ ASCII وSTX/ETX وإطار YAOHUA A9+ تلقائيًا، ولا يعتمد البرنامج الاتصال إلا بعد استقبال ثلاث قراءات وزن متقاربة.
- إعدادات COM والبروتوكول اليدوية مخفية ضمن إعدادات متقدمة، للاستخدام عند الحاجة فقط.
- إعدادات Serial موسعة: Baud Rate قابل للإدخال، وData Bits وParity (None/Even/Odd/Mark/Space) وStop Bits وRTS/CTS.
- تجربة تلقائية لمجموعة من سرعات الاتصال وإعدادات Parity الشائعة، مع تثبيت الإعداد الذي يستقبل قراءة رقمية.
- وضع إدخال يدوي بديل مع توضيح مصدر الوزن في التذكرة.
- بروفايلات إعداد أولية لعدد من مؤشرات الوزن، مع وضع Generic قابل للتخصيص.
- اتصال TCP مباشر بمؤشر الوزن على الشبكة المحلية (LAN) دون إنترنت.
- ملف Excel مرتبط تلقائيًا: تتم مزامنته بعد كل تذكرة في Documents/Weighbridge 120T/Weighbridge-120T-Records.xlsx، ويمكن تغيير مساره أو فتحه من سجل الوزن.
- يحتوي المصنف على ورقتين: سجل التذاكر وتفاصيل الوزنتين، مع حفظ القراءة الأصلية والوزن المعتمد وأي فرق تعديل يدوي.
- تصدير نسخة Excel مستقلة متاح أيضًا من سجل الوزن، ويعمل من مكتبة XLSX المحلية المرفقة مع التطبيق.
- التثبيت لا يتطلب متصفحًا أو خادمًا محليًا أو خدمة سحابية.

### بناء نسخة Windows

المتطلبات لبناء البرنامج فقط: Windows، Node.js 22 أو أحدث، واتصال إنترنت أثناء تنزيل حزم البناء أول مرة. **البرنامج الناتج لا يحتاج إنترنت للتشغيل.**

```bash
npm install
npm run dist:win
```

النواتج داخل مجلد `release/`:
- مثبت Windows بصيغة NSIS.
- نسخة Portable بصيغة EXE.

يمكن أيضًا تشغيل البناء من GitHub Actions عبر:
**Actions → Build Windows Desktop App → Run workflow**.
سيتم رفع ملفي EXE كـ Artifact باسم `Weighbridge-Simulator-Windows`.

## التخزين والبيانات

- Web Edition: Local Storage في المتصفح.
- Windows Edition: SQLite محلية في جهاز المستخدم.
- لا توجد مزامنة سحابية أو إرسال تلقائي للبيانات.
- احتفظ بنسخة احتياطية من ملف `weighbridge.sqlite` عند الحاجة لنقل السجلات إلى جهاز آخر.

## توحيد حسابات الدخول على الشبكة المحلية

يمكن تشغيل جهاز واحد كمركز لحسابات الدخول، بحيث تتحقق بقية أجهزة Windows من اسم المستخدم وكلمة المرور وإدارة المستخدمين من قاعدة حسابات الجهاز المركزي. لا يحتاج ذلك إلى إنترنت، لكن يجب أن يكون جهاز المركز قيد التشغيل وعلى نفس الشبكة المحلية.

### إعداد جهاز المركز

1. اختر الجهاز الذي يحتوي حاليًا على الحسابات الصحيحة وكلمة المرور المعتمدة (مثل الجهاز الذي يقبل 6666). أغلق البرنامج عليه.
2. افتح ملف الإعدادات `network.json` داخل مجلد بيانات البرنامج في `%APPDATA%\weighbridge-simulator\` بجوار ملف `weighbridge.sqlite`. إذا اختلف اسم المجلد على جهازك، ابحث عن ملف `weighbridge.sqlite` داخل مجلد بيانات التطبيق نفسه.
3. أنشئ مفتاحًا عشوائيًا من 64 خانة hex من PowerShell أو Terminal باستخدام:
   `node -p "require('node:crypto').randomBytes(32).toString('hex')"`
4. اجعل محتوى `network.json` على جهاز المركز بالشكل التالي، مع وضع المفتاح الناتج:

```json
{
  "mode": "host",
  "bindAddress": "0.0.0.0",
  "port": 3210,
  "serverUrl": "",
  "sharedKey": "ضع_هنا_المفتاح_العشوائي_64_خانة"
}
```

5. اسمح بالاتصال الوارد على TCP port 3210 في شبكة Windows الخاصة. يمكن تنفيذ الأمر التالي من PowerShell كمسؤول:
   `netsh advfirewall firewall add rule name="Weighbridge Central Auth" dir=in action=allow protocol=TCP localport=3210 profile=private`
6. شغّل البرنامج على جهاز المركز. استخرج عنوان IPv4 له باستخدام `ipconfig` واحتفظ بعنوان الشبكة المحلية.

### إعداد بقية الأجهزة

على كل جهاز عميل، أغلق البرنامج وافتح ملف `network.json` الموجود في مجلد بياناته، واجعل محتواه:

```json
{
  "mode": "client",
  "bindAddress": "0.0.0.0",
  "port": 3210,
  "serverUrl": "http://192.168.1.20:3210",
  "sharedKey": "نفس_المفتاح_العشوائي_الموجود_على_جهاز_المركز"
}
```

استبدل `192.168.1.20` بعنوان IPv4 الحقيقي لجهاز المركز، وانسخ قيمة `sharedKey` نفسها حرفيًا إلى كل الأجهزة. بعد ذلك شغّل البرنامج على الأجهزة العميلة. عندما يكون الجهاز في وضع `client`، لا يستخدم كلمات مرور الحسابات المحلية القديمة ولا يرجع إليها عند انقطاع الاتصال؛ بل يعرض خطأ اتصال ويطلب عودة الخادم المركزي.

### ما الذي يصبح مركزيًا؟

تسجيل الدخول، تغيير كلمة المرور، تغيير اسم الدخول، إضافة المستخدمين، إعادة تعيين كلمات مرورهم، إيقافهم أو تفعيلهم، وحذفهم؛ كلها تنفذ على قاعدة حسابات جهاز المركز. تشفير AES-256-GCM يحمي بيانات طلبات الحسابات أثناء انتقالها عبر الشبكة المحلية. تبقى واجهة البرنامج كما هي.

**ملاحظة مهمة:** في الكود الحالي، ملف `weighbridge.sqlite` وسجلات الوزن ما زالا محليين داخل مجلد بيانات كل نسخة Windows. هذا التعديل يوحّد الحسابات فقط ولا يحوّل سجلات الوزن إلى قاعدة مركزية. لا تفترض أن سجلات الأجهزة متزامنة لحظيًا بسبب هذا التعديل.

## البروتوكولات والتوافق

البرنامج يوفّر محرك قراءة قابلًا للتوسعة لرسائل ASCII وCR/LF وSTX/ETX وتدفق البيانات، مع إعدادات اتصال Serial وTCP وتجربة تلقائية لإعدادات Serial الشائعة. ملفات التعريف الظاهرة في الواجهة هي إعدادات/أنماط أولية وليست شهادة بأن كل موديلات Rice Lake أو كل بروتوكول مغلق مدعوم بالفعل.

دعم كل مؤشر يتطلب اختبار بروتوكوله الفعلي: صيغة الإطار، أوامر الطلب، وحدات الوزن، حالات الاستقرار/الحركة، ورسائل الخطأ. بعض الأجهزة تستخدم بروتوكولات ثنائية أو أوامر خاصة أو USB HID؛ تُضاف لها Drivers/Parsers مستقلة عند توفر دليل الشركة أو عينة اتصال. اتصال TCP الحالي هو TCP client، وليس ماسحًا تلقائيًا لكل أجهزة الشبكة أو دعمًا عامًا لكل UDP.

## دعم مؤشر YAOHUA XK3190-A9 / A9+

تتضمن إعدادات الاتصال ملفًا مخصصًا لإطار YAOHUA A9+ في وضع الإرسال المستمر (tF=0):
- استقبال الإطار المحاط بالبايتين STX (0x02) وETX (0x03).
- قراءة علامة السالب/الموجب، وستة أرقام، وموضع العلامة العشرية.
- التحقق من بايتي XOR قبل اعتماد الوزن؛ الإطارات غير المكتملة أو غير الصحيحة لا تغيّر القراءة.
- إعداد Serial مبدئي 9600 baud و8 data bits وNo parity و1 stop bit، ويمكن تغييره ليتطابق مع إعداد المؤشر. الدليل يذكر سرعات 600/1200/2400/4800/9600، وإعدادات المؤشر تُضبط من قائمة الاتصال.

**تنبيه التوصيل:** دليل A9+ الذي تمت مراجعته يصف منفذ اتصال مشتركًا من نوع 15-pin ويحدد إشارات RS232 على أطرافه 6/7/8؛ لذلك لا تفترض أن DB9 هو منفذ المؤشر نفسه. قد يكون DB9 طرف محول/كابل. يجب مطابقة مخطط جهازك الفعلي قبل توصيل الأسلاك لتجنب تلف المنفذ. كما أن هذا التعريف مؤكد لبروتوكول A9+؛ بعض إصدارات A9 قد تختلف، ويظل وضع Generic متاحًا للاختبار.
